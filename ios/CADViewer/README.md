# CADViewer

The SwiftUI layer: routes a file to the engine that can show it, and provides gestures,
zoom controls and error reporting.

```swift
RootView()   // the whole app
```

## Routing

`DrawingKind(fileName:)` decides:

| Kind | Goes to | Why |
|---|---|---|
| `.dxf` | `DrawingLoader` → `DXFViewer` | SwiftDXF is pure Swift, so the geometry becomes a canvas |
| `.dwg` | `DWGViewer` | no open native parser exists; the bundled wasm engine draws it |
| `.pdf` | `PDFViewer` | `PDFKit` already does scrolling, zoom, selection and links |

Anything else is refused with the extension named, rather than opening a blank canvas.

## Files this layer owns

| File | Role |
|---|---|
| `RootView` | the only screen: pick a file, show it, report failures |
| `DrawingLoader` | reads and flattens a DXF off the main thread |
| `DXFViewer` | the native reading surface: gestures, controls, details sheet |
| `DrawingCanvas` | draws the scene with `Canvas`, culling off-screen primitives |
| `PDFViewer` | wraps `PDFView`; fits the page or the width |
| `DWGViewer` | hosts the bundled web viewer and relays its progress |
| `ViewerSchemeHandler` | serves the bundle over `cadviewer://` so wasm and workers load |

## Why a custom URL scheme

`file://` blocks `fetch`, Web Workers and `WebAssembly.instantiateStreaming`, so the
LibreDWG wasm cannot start. A `WKURLSchemeHandler` gives the page a real origin while
everything still comes from the app bundle. The handler also answers `__dwg__` with the
drawing bytes, so nothing large is passed through a URL string.

## Resource

`Resources/dwgviewer` is generated by `../web/build-for-ios.sh` and copied into the bundle
by SwiftPM. It is not edited by hand.

## Tests

There is no test target here, deliberately. Every file in this package is SwiftUI, WebKit
or PDFKit, which needs a simulator to exercise at all; a test target could only reach the
boring parts and would imply coverage the layer does not have.

Everything that could be tested was moved to `DXFGeometry`:

| Moved | Now tested by |
|---|---|
| `DrawingKind` (the routing decision) | `FileRoutingTests` |
| `LoadFailure` (the messages a reader sees) | `FileRoutingTests` |
| `ViewTransform` (pan, zoom, fit) | `ViewTransformTests` |
| the flattening | `SceneBuilderTests` |

Run them with `swift test` in `../DXFGeometry`, or `./run.sh verify` in
`../../verification/dxf-geometry-harness` on a machine without an Apple SDK.
