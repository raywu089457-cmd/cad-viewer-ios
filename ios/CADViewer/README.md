# CADViewer

The SwiftUI layer: routes a file to the engine that can draw it, and provides gestures,
zoom controls and error reporting.

```swift
RootView()   // the whole app
```

## Routing

`DrawingKind(fileName:)` decides. `.dxf` goes to `DrawingLoader` →
`DXFViewer`; `.dwg` goes to `DWGViewer`. Anything else is refused with the extension named,
rather than opening a blank canvas.

## Files this layer owns

| File | Role |
|---|---|
| `RootView` | the only screen: pick a file, show it, report failures |
| `DrawingLoader` | reads and flattens a DXF off the main thread |
| `DXFViewer` | the native reading surface: gestures, controls, details sheet |
| `DrawingCanvas` | draws the scene with `Canvas`, culling off-screen primitives |
| `DWGViewer` | hosts the bundled web viewer and relays its progress |
| `ViewerSchemeHandler` | serves the bundle over `cadviewer://` so wasm and workers load |

## Why a custom URL scheme

`file://` blocks `fetch`, Web Workers and `WebAssembly.instantiateStreaming`, so the
LibreDWG wasm cannot start. A `WKURLSchemeHandler` gives the page a real origin while
everything still comes from the app bundle. The handler also answers `__dwg__` with the
drawing bytes, so nothing large is passed through a URL string.

## Resource

`Resources/dwgviewer` is generated by `../web/build-for-ios.sh` and copied into the bundle
by SwiftPM. It is not edited by hand.

## Tests

`Tests/CADViewerTests` covers the routing. Everything else here needs a simulator, which is
why the arithmetic lives in `DXFGeometry` where it can be tested without one.
